# NYXI 无通知邮件补丁：本地验收

## 结论

按次关闭通知的Zoho补丁已实现并完成模拟验证，未接入生产执行器、未部署、未发送测试或真实邮件。

基线 `d7030af`，独立分支 `codex/nyxi-mail-no-notify`。初始提交 `1d58e4f`，随后修复发送后取消并补充回归测试。原工作目录已有其他任务改动，本分支没有复制或修改它们。

## 行为

- `send_email(..., notify=False)`：发送前继续检查草稿原文，发送后等待原文长度检查；结果异常不发飞书通知。
- 邮件已被Zoho接受、但查询异常/内容截断/等待被取消：抛 `SentVerificationError`，保留 `message_id`、`send_accepted=True` 和原因。执行器必须停止当前批次并回查，禁止将其当作未发送重试。
- 不传参数的既有调用：后台校验及原告警行为保持不变。
- 本次没有改变品牌凭据、生产环境变量、auto_send、发信额度或停止条件。

## 验证

1. 12项专项模拟测试全部通过：关闭通知、默认告警、原文读取、截断、查不到邮件、网络异常、草稿不通过禁止发送、发后异常保留编号、取消、默认后台任务清理、并发调用策略隔离、非法参数。
2. 全仓离线检查1,133项，1,131项通过；2项因为禁启动子进程被拦截。阅读源码确认仅临时SQLite并发和PowerShell SelfTest后，单独补跑2项通过。未让测试使用真实凭据或外部服务。
3. Standards与Spec独立审查各发现同一取消缺陷；修复并复查后均关闭。默认后台校验兼容性测试也已补齐。
4. `git diff --check`通过。

运行测试需显式把当前仓库放在Python模块搜索首位；本机嵌入Python原路径会误加载其他项目的同名`app`。

## 上线前仍必须完成

此补丁只覆盖Zoho模块，不覆盖auto_send的其他告警，也不提供候选级业务防重、主表登记或回复承接。不能直接调用全表auto_send来验证。

下一阶段应复用既有执行与记录机制，明确NYXI候选范围、无通知记录方式、已接受但未核实结果的持久记录与只回查规则；再做测试邮箱原文/实际客户端渲染及首封观察。进程被强行终止仍需从持久发送记录及发件箱对账，函数内异常不能替代这一层。原有长度检查也不是送达证明。
