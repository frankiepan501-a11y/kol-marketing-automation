# KOL集中宣发：待审旁路与体量优先修复交接

## 结论

本次把活动候选的人审从“主流程闸门”改为“并行旁路”。边界候选继续留给KOL运营批量审核，但不会阻止系统继续寻找、筛选、补入和发送其他明确合格对象。

## 问题与根因

1. `append_auto_approved` 默认在存在任何待审核对象时直接返回，通用活动入口会停止补入。
2. 即使去掉直接返回，旧容量公式仍把待审对象计入池目标；当20名待审占满20名目标时，系统仍会静默停止。
3. 食人花低产后会进入 `quality_cooldown`，整轮创建0个发现任务；在邮箱仍有额度、可发送库存仍不足时，这与集中宣发的时限目标冲突。

## 改动

- `app/launch_runtime.py`
  - 所有活动入口统一允许待审与明确合格对象并行。
  - 待审对象不占用明确可开发池目标名额。
  - 待审对象仍不得生成草稿或发送。
  - 自治补池按非待审活跃数计算追加上限，避免重复扩容。
- `app/keyword_supply.py`
  - 新增 `volume_priority` 控制；活动有库存缺口时，低产冷却改为继续有上限地换词发现。
  - 保留每轮任务上限、在途去重、模型预算及全部硬筛选。
- `tests/test_launch_runtime.py` / `tests/test_keyword_supply.py`
  - 增加20名待审占满目标仍继续补入的边界测试。
  - 增加食人花低产冷却仍继续发现、但不降低筛选条件的测试。
