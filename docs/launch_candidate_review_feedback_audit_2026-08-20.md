# 食人花候选审核反馈反哺审计（2026-08-20）

## 结论

本次 20 名食人花候选中，1 名通过、18 名排除、1 名待补资料。误选不是单一字段错误，而是四处规则叠加造成：

1. KOL 主表的「内容风格」只有“游戏 / 测评 / 综合”等粗标签；Switch 底座规则又允许“游戏”单独命中，泛游戏频道因此通过基础筛选。
2. 17/20 名候选没有 `v2` 标签版本；16/18 名被排除对象没有近期视频标题和抓取时间，系统没有先补资料，而是把缺口转给人工审核。
3. `IP喜好` 已包含 Roblox、Minecraft、Fortnite、影视、PC 速通等大量反向信号，但当前算法只在命中产品 IP 时加分，未命中不扣分也不拦截。
4. 全局触达预检只在命中同产品草稿后才使用“洽谈中”等正向关系状态；因此存在主表已是“洽谈中”，仍被判为 `eligible_new_cold` 的情况。

## 最小字段方案（不新建第二张 KOL 主表）

主表只增加或标准化客观、跨产品可复用的事实：

1. `内容垂类`：游戏硬件评测 / 主机游戏 / PC游戏 / 手游 / 泛游戏娱乐 / 科技非游戏 / 影视娱乐。
2. `主机生态`（多选）：Switch / Switch 2 / PlayStation / Xbox / PC-Steam / Mobile / 跨平台。
3. `最近发布日`、`近90天发布数`：用于判断是否有能力在活动窗口上稿。
4. `资料可用状态`：有效 / 人工核实有效 / 待刷新 / 缺资料 / 活跃度不足，由标签版本、抓取时间、近期内容或人工结论计算。
5. `资料核实时间`：记录人工结论何时产生；超过60天自动失效，禁止把“人工核实有效”当永久白名单。
6. `触达路由状态`：可新开发 / 沿用原线程 / 禁止新开发 / 待核对，由合作状态和全局草稿/跟进历史计算。

活动参与记录表增加 `审核原因代码`（多选），保留现有 `审核原因` 作为人类说明。建议代码：

- 目标主机不匹配
- 核心游戏/IP不匹配
- 硬件/配件内容不足
- 非游戏或泛娱乐
- 活跃度不足
- 地区/语言不匹配
- 历史关系冲突
- 资料缺失或过期
- 通过：Nintendo/Switch强匹配

产品特定的“不适合食人花”不得直接把 KOL 主表改成“不合适”；否则该达人可能被其他产品错误永久排除。主表只回填客观画像，产品适配结论留在活动参与记录。

## 食人花活动的新筛选顺序

1. 全局触达路由：洽谈中、已合作、同线程待回复等对象禁止进入“新开发”。
2. 资料有效性：`v2` 且内容数据在 60 天内；否则先后台刷新，不交给人工。
3. 国家、语言、主平台硬筛。
4. 产品受众硬筛：必须命中 Switch/Switch 2，且满足 Nintendo/Mario IP 或近期硬件评测、开箱、SETUP 内容之一；“游戏”不能单独通过。
5. 活跃度硬筛：近 90 天发布量达到活动最低标准；低频但高度匹配者进入“待补资料/例外池”。
6. 通过以上规则后，才按粉丝量、历史表现、竞品证据排序。
7. 人工只审核边界项；明显 Roblox/Minecraft/Fortnite/影视/非游戏对象由系统先排除。
