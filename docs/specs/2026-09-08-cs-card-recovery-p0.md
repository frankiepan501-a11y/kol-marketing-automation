# 客服助手 8 月 23 日后断流 P0 修复规格

## 背景

FUNLAB 邮箱自 2026-08-24 起至少 130 封消息未进入客服工单台；生产派卡同时处于未显式配置的观察模式。n8n 定时器持续显示 success，业务却没有新工单或新卡。

## 必须实现

1. FUNLAB 邮箱账号或授权码缺失时，采集结果必须在 `source_errors.funlab` 明确失败，接口不得继续返回业务 `ok=true`。
2. 提供受鉴权的单封 FUNLAB 邮件回放入口；以请求体传 `message_id`，支持 `dry_run`，复用原有去重、分类和写表逻辑。
3. 派卡必须要求显式配置 `CS_DISPATCH_OBSERVE` 和 `CS_DISPATCH_OBSERVE_UNION`；缺失时停止发卡并返回配置错误。
4. 派卡返回必须包含收件模式、收件人解析兜底和飞书发送失败原因；发送失败时接口不得业务 `ok=true`。
5. 定时派卡只处理修复时间之后的新工单；历史补录需按 `record_id` 明确放行，防止卡片风暴。
6. 不改变客服助手 App、工单 Base、字段名、按钮 action 或回调入口。

## 生产恢复

1. 暂停采集和派卡 cron。
2. 单变量恢复邮箱和观察模式配置，禁止全量 env 覆盖。
3. 先用 5 封 dry-run 实测耗时和分类，再分批回放全部缺失邮件；补采期间保持 Frankie-only。
4. Frankie-only 样卡和回调通过后，才切 `CS_DISPATCH_OBSERVE=0` 并恢复自然 cron。

## 安全边界

- 不把真实客户作为测试对象。
- 不批量补发 130 张卡；历史工单先分类、统计、再由明确范围派卡。
- 不启用客户自动回复；本次不修改邮件模板。
