# Dave 外部 YouTube 发现词续供设计（方案 A2）

日期：2026-08-25
状态：Frankie 已确认按 A2 口径修订并进入 TDD 实现

## 目标

当 Dave 集中宣发活动扫描现有 KOL 主表后仍缺少有效可发送库存时，系统按活动和产品资料创建外部 YouTube 创作者发现任务，并把外部发现的新作者写回 KOL 主表供下一轮结构化筛选。它替代的是运营逐轮决定“还要去 YouTube 搜什么”这一重复决策，不改变 KOL 是否合格的判断门槛。

本规格中的“发现词”只指交给外部 YouTube 搜索的查询词，不是 KOL 主表的全文检索词。当前实现不同时搜索 TikTok 或 Instagram；这两个平台仍走各自独立链路。

## 当前问题

生产自然轮次 `launchruntime-474ed084e29b` 已证明人工待审没有阻塞主流程，但 Dave 没有创建新的外部 YouTube 发现任务；当日 DeepSeek 预算又达到 60/60，因此可发库存仍为 0。当前代码把爬虫任务台所有历史完整关键词永久视为“已使用”，没有区分国家、语言和执行时间；因此“确定性词源耗尽”实际只表示历史任务去重后没有新字符串，不代表 KOL 主表里没有合适对象，也不代表 YouTube 搜索结果为 0。

## 方案

Dave 的自动补池保留三类供给来源，顺序固定：

1. **历史关系直接源**：现有主表和活动预览先处理同品类历史优质关系及仍可合法重新建联的对象；它与竞品配置无关，任何模式都先运行。已上稿同产品、正在洽谈、拒绝、退信或命中重复触达的对象仍由现有硬规则排除。
2. **可选竞品证据直接源**：只有活动明确选择并锁定竞品证据时，才继续处理未匹配的竞品作者。Dave 本次是 NYXI；以后其他活动是否使用竞品、使用哪个竞品，完全由活动配置决定。
3. **外部 YouTube 搜索发现源补缺口**：两类直接源处理完本轮额度后，如果有效可发送库存仍低于目标，才启动确定性七层发现词。待审核对象不算可发送库存，也不会阻止搜索继续补池。

三类来源分别汇报处理量、合格/可运营审核量、排除量和主要原因，不能把“历史关系或竞品直接源有产出”写成“外部搜索有产出”，也不能把创建任务数当成候选人数。

外部 YouTube 搜索发现源在 `ensure_campaign_supply()` 的 Dave 自动路径中，按以下顺序取词：

1. 继续优先使用尚未用过的旧固定词，保持兼容。
2. 固定词不足时，调用 Dave 七层确定性外部发现词编译器。
3. 固定组合不足时，从符合意图过滤、对应来源健康且已超过 7 天窗口的历史组合中轮转；同等条件下优先历史有效邮箱或可用候选产出大于 0 的组合，未知产出次之，明确零产出的组合最后；仍不足才报告真实缺口。本次不提高 DeepSeek 预算，也不依赖模型才能续供。

七层信息为：

| 层级 | Dave 示例 | 作用 |
|---|---|---|
| 可选竞品 | 仅当活动明确选择且证据已就绪时使用活动配置中的品牌 | 不把 NYXI 写成全局默认 |
| IP/主题 | Dave the Diver、cozy indie game、fishing game、restaurant management game | 找到游戏/IP及邻近兴趣受众 |
| 主机平台 | Nintendo Switch 2、Nintendo Switch | 锁定目标主机生态 |
| 品类/功能 | controller、gamepad、gaming accessory | 锁定硬件评测创作者 |
| 玩家场景 | indie gamer、cozy gamer、Nintendo fan、handheld gamer | 扩充邻近受众 |
| 内容形式 | review、gameplay review、unboxing、hardware test、setup tour、accessories roundup | 把主题变成创作者搜索意图 |
| 市场本地化 | en、de、es | 按活动国家和语言生成当地表达 |

每个词至少组合两个信息轴；IP词优先组合平台或内容形式，避免再次出现“Dave人名、真实潜水、垃圾箱潜水”等歧义。词源按来源轮转，避免一个来源占满整批；英语为主，同时保留德语和西班牙语覆盖。

## 数据流

```text
活动/产品字段
  → 历史关系直接源：现有主表/活动预览中的合格可复用关系
  → 可选竞品证据直接源：仅当前活动锁定的竞品作者
  → 两类直接源都做身份归并、国家、语言、邮箱、历史关系与重复触达预检
  → 历史关系、竞品证据的本轮结果分别记账
  → 重新读取有效可发送库存；仍不足才进入外部YouTube搜索发现源
  → 按“完整关键词＋国家＋语言”读取历史任务及最近执行时间
  → 优先选7天内没有执行过、且当前没有在途任务的固定词
  → Dave七层编译器按健康来源和语言轮转补足
  → 购买/店铺/官方意图过滤
  → 每轮最多3～9个爬虫任务
  → 陈翔宇部署终端的现有daemon异步搜索YouTube并写回KOL主表
  → 下一轮活动预览重新按结构化字段筛选，再进入草稿与唯一发送中心
```

历史关系直接源继续复用现有全池预览、自动通过追加和审核旁路，不新增另一套名单。可选竞品证据直接源保持当前每轮抽取20名证据作者、最多写入3名合格/可运营审核对象的安全上限；没有活动竞品配置时只跳过竞品证据子源，历史关系直接源仍照常运行，不得自动套用 NYXI。

任务名继续写入活动 ID，并为结构化发现词增加 `词源`。部署终端执行任务时，必须把`活动ID＋爬虫任务record_id＋词源＋本轮发现词`写入每条新KOL的「迁移备注」；活动预览只有同时匹配当前活动和当前任务record_id时才确认归因，并按`by_task`逐轮回读原始发现、有效邮箱、系统明确合格、可运营审核和排除原因。只看到相同关键词或孤立`[词源:*]`标签时一律归为`unknown`，防止其他活动或更早轮次污染当前活动的来源健康。A2以前受控的Dave固定任务本身可按固定词表还原为`legacy_fixed`，但旧KOL记录没有活动/任务标记时不得猜测归因。已有国家、语言、活跃度、内容、邮箱、历史关系、重复触达及发送证书闸全部保持不变。

## 三层结果口径

每次自治任务必须分别输出以下三层，不得再用一个“补池数量”混写：

| 层级 | 字段 | 说明 |
|---|---|---|
| 内部主表筛选 | `internal_pool` | 本轮扫描主表人数、明确合格、可运营审核、被硬规则排除、进入草稿队列人数 |
| 外部发现任务 | `external_youtube_discovery` | 新建、在途、近期已跑而跳过、来源冷却而跳过、真实缺口的 YouTube 任务数 |
| 外部发现结果 | `external_youtube_outcome` | 已完成任务的原始发现、新增、更新、有效邮箱、明确合格、可运营审核及主要排除原因 |

“外部发现任务已创建”只表示异步任务进入飞书爬虫任务台；必须等部署终端完成任务、写回主表并经过下一轮活动筛选后，才能形成“外部发现结果”。

`raw_discovered`只允许读取任务表中明确的原始发现字段或执行日志信号；如果当前daemon只提供“新增＋更新”，则该值保持未知/0并记录信号覆盖数，“新增＋更新”单列为`records_written`，不得冒充原始发现人数。

## 低产、轮转与停止规则

### 来源级统计口径

- 一个“来源轮次”指该 `词源` 最新完成的一条爬虫任务；同一批次优先每个健康来源只取一条，再进入下一轮，避免单一来源占满任务。
- 每个来源回读最近两条已完成任务，分别记录：原始发现数、有效邮箱数、系统明确合格数、可运营审核数、排除数和主要排除原因。
- 内部筛选结果必须按爬虫任务`record_id`回填到对应轮次；`by_source`和`by_keyword`累计值只用于日报展示，不能覆盖最近两轮任务的未知或零产出。
- 某位KOL首次进入活动参与记录时，系统把当时的“系统建议通过／KOL运营审核”作为该爬虫任务的不可变筛选快照。之后即使发信后关系状态变成已有线程，也不能把这次历史正产出重算成0；只有原本没有活动参与快照的对象才按当前筛选结果记账。
- `可用产出 = 系统明确合格 + 可运营审核`。可运营审核对象必须已经通过国家、语言、有效邮箱、历史关系和重复触达等确定性门槛，只允许内容语义或资料边界留给运营；因此它可以证明来源仍有价值，但仍不得自动进入草稿。

### 冷却和恢复

- 同一来源连续两个已完成轮次的可用产出都为0，该来源进入2小时冷却，当前运行立即换下一个健康来源。
- 冷却期间即使 `volume_priority=true` 也不得继续堆该来源；体量优先只能加快使用其他健康来源，不能覆盖来源级停损。
- 2小时后来源只恢复1条探测任务。探测产生至少1名可用对象则恢复正常轮转；仍为0则重新冷却2小时。
- 冷却起点使用第二个零产出任务变为“3-已完成”并写入执行日志时，飞书记录返回的持久 `last_modified_time`；读取任务时必须带 `automatic_fields=true`。任务创建时间不能作为冷却起点。已完成记录缺少 `last_modified_time` 时按信号缺失处理，不自行猜时间。
- 来源健康统计键固定为“活动 ID＋词源”，Dave 某个来源的低产不会影响食人花或其他活动的同名来源。
- 已完成爬虫任务不自动等于“已完成内部筛选”。有效邮箱为 0 时可以确定其可用产出必为 0；有效邮箱大于 0、但尚未完成来源归因和下一轮内部筛选时，结果状态为 `pending/unknown`，不得按 0 参与连续低产判断。只有“确定没有有效邮箱”或已经回填来源归因后的明确合格＋可运营审核均为 0，才能记为来源级 0 产出。
- 轮转位置不存进程内存。系统每次从飞书任务表按词源的最后创建时间、最后完成时间和历史使用次数重建，选择“未冷却且最久未使用”的来源，因此服务重启或重新部署后不会从第一个来源重新开始。
- 从未创建过任务的新来源视为健康来源，可以正常进入首轮，不属于信号缺失。
- 当前活动整体的有效邮箱和合格转化低产判断继续保留；活动级慢速探测不能取消来源级冷却。只有“已有已完成任务，但执行日志、来源标签或 `last_modified_time` 缺失”才按失败关闭处理：最多建立1条探测任务并返回 `source_signal_unavailable`，不恢复整批扩池。

### 其他停止条件

- 去重键为“规范化完整关键词＋排序后的目标国家＋目标语言”，不能只按关键词字符串全局永久去重。关键词规范化固定为 Unicode NFKC、大小写折叠、首尾空白去除、连续空白压成一个空格；内部标点保留，避免把含义不同的搜索词误并。
- 相同去重键存在待触发或执行中任务时不重复创建；最近一次完成时间距今不足7天时标记 `recently_executed`，不重复创建。
- 最近一次任务完成已超过7天，且对应来源未处于来源级冷却时，允许重新创建同一去重键。这样能发现后来出现的新作者，也避免每小时重复抓同一搜索结果。
- 从未运行的新组合优先于7天后允许重跑的历史组合；同一批次内仍保持唯一。
- 如果所有来源都在冷却、统计信号缺失、全部组合仍在7天窗口或确实没有可生成组合，必须返回 `shortfall_tasks`、`source_health`、`keyword_history_state` 和明确原因。原因必须区分 `active_duplicate / recently_executed / source_cooling / source_signal_unavailable / deterministic_combinations_exhausted`，不能再笼统写“备用词用完”。

## 测试边界

公开测试入口为 `ensure_campaign_supply()`：

1. 模拟 Dave 旧固定词和已生成结构化词都在历史任务中出现，但已超过7天，仍可按“关键词＋国家＋语言”得到4个可重跑发现词。
2. 4个词至少覆盖3个健康来源，语言分布为英语主、德语和西班牙语辅。
3. 竞品模式关闭时，任何词不得出现 NYXI 或历史竞品名。
4. 购买、价格、优惠、店铺、官方频道意图继续被拒绝。
5. 真实写任务时保持目标国家/语言、每批50、任务状态待触发、活动ID和词源标签。
6. 构造同一来源连续两轮可用产出为0，下一轮必须跳过并切换来源；2小时未满不能被体量优先覆盖，2小时后只能建立1条恢复探测。
7. 模拟服务重启后重新读取同一批任务，轮转仍从最久未用的健康来源继续，不重复从第一来源开始。
8. 相同词在不同国家/语言组合下不会被错误视为同一任务；相同组合7天内不重复、超过7天可重跑，在途任务无论年龄都不重复。
9. 返回值分别包含 `keyword_history_state`、`external_youtube_discovery` 可解释计数，且确定性发现词不消耗 DeepSeek 调用。
10. `quality_filters_lowered=false`。
11. 其他活动的来源标记、相同关键词的旧轮次、被邮箱/关系/重复触达硬规则拦截但进入人工路由的对象，均不能让当前任务轮次恢复为健康。

运行时顺序和端到端安全测试：

1. Dave 供给不足时，必须依次处理历史关系直接源、可选竞品证据直接源，再创建外部 YouTube 搜索任务；三类结果保存在不同字段。无竞品模式只跳过竞品证据，不能跳过历史关系。
2. 待审核对象不占有效可发送库存、不阻止继续补池，也不得进入 `queue_approved()`。
3. 构造越界国家/语言、无效或缺失邮箱、同邮箱重复身份、历史已触达/同产品已上稿对象，逐条断言：不能成为审核通过参与人、不能创建草稿、不能进入发送队列。
4. 构造仅内容语义不确定但其他硬门槛通过的对象，断言：只能进入运营待审核旁路；下一轮补池仍继续，草稿数和发送数保持0。
5. 构造系统明确合格对象，断言它仍需经过现有参与记录、全局重复触达预检和唯一发送中心，不允许关键词模块直接建草稿或发信。

## 上线与验收

- 只修改 Dave 直接源/外部YouTube搜索源的供给顺序、发现词历史窗口、三层指标、来源健康统计与相应测试；不改 n8n、邮箱额度、候选筛选标准、草稿模板或发送器。
- 部署前确认 Dave 和食人花没有正在运行的后台补池任务。
- 部署后不手动触发，等待 Dave 整点自然轮次。
- 首次自然轮次验收历史关系、可选竞品证据、外部YouTube发现的顺序与三层独立计数；若有健康来源和符合7天规则的组合，创建发现任务并使 `shortfall_tasks=0`。
- 爬虫任务完成后的下一自然轮次再验收来源健康：连续两轮0可用对象的来源必须冷却并自动换源；不能只看到“新建4个任务”就宣布完成。
- 端到端抽样回放必须证明越界市场、无邮箱、历史冲突、重复身份和待审核对象均未进入草稿/发送队列。

## 非目标

- 本次不把 Dave/NYXI 固化成所有产品的默认竞品。
- 本次不提高 DeepSeek 日预算。
- 本次不把待审核候选直接生成草稿或发信。
- 本次不把 Dave 发现词同时下发到 TikTok/Instagram；跨平台供给另行设计和验收。
- 本次不把 Dave 专用灰度直接声明为所有产品的通用正式规格；待本轮真实产出验证后再抽象成通用产品词池。
