# Dave 可选竞品证据与七层词源灰度分析（非正式规格）

状态：v1、v2真实灰度均未通过；正在验证“竞品证据直达候选＋关键词仅做补充发现”的修正版。本文件仍不是正式规格。

## 结论

Dave 使用 NYXI 只是首个灰度实例。以后每个 KOL 集中宣发任务独立选择：新建竞品调查、引用历史竞品证据、或不使用竞品证据。系统不能把产品名与某个固定竞品绑定。

七层信息仍然保留：可选竞品、IP/主题、适配平台、品类/功能、用户身份/场景、内容形式/达人类型、市场本地化。但真实灰度证明，不能把七层信息全部降级为“关键词”。竞品已合作达人和历史优质关系应直接进入候选源；关键词只承担补充发现，并用真实合格候选产出自动保留、扩展、冷却或换源。

## 第一性原理检查

| 问题 | 本次判断 |
|---|---|
| 是否创造价值 | 是。目标是增加合适且可触达的 KOL 供给，不是增加爬虫任务数。 |
| 是否解决真实问题 | 是。Dave 已出现可发送库存0、固定词耗尽、仍有邮箱余量的真实卡点。 |
| 是否有实践反馈 | 是。最近12个任务有13个有效邮箱，但24小时新增审核通过为0，证明“有邮箱”不等于“有合适候选”。 |
| 是否快速迭代 | 已用 Dave 连续做两轮小批灰度；失败后停止继续堆更长关键词，转查发现方式本身。 |
| 是否验证模型 | 灰度必须回读词源、有效邮箱、硬筛选结果和合格候选，而不是只看接口成功。 |
| 是否可系统复制 | 竞品、产品、平台和市场均来自活动配置；Dave/NYXI只作为一组输入。 |
| 是否形成杠杆 | 通过自动换词和低产冷却替代 Frankie/运营逐轮补词决策。 |

企业改造层级为 L2＋L3＋L4：系统替代选词能人；运营只交产品、市场和可选竞品；Frankie 审规则和异常，不审普通关键词和普通候选。

## 任务输入与系统获取

运营必填：产品、上稿窗口、目标KOL数、市场、语言、平台、竞品模式。选择竞品时再填竞品品牌，型号可选。

系统自动读取：产品英文名、品类、适配平台、IP/主题、已确认功能、历史触达、合作状态、人工排除原因、竞品证据、关键词历史产出和邮箱额度。

### 修正后的两条供给通道

| 通道 | 输入 | 正确动作 | 失败时怎么处理 |
|---|---|---|---|
| 直接候选源 | 已确认竞品合作达人、历史优质合作、已匹配的竞品帖子作者 | 直接做身份归并、国家/语言/邮箱/历史关系预检，不先生成关键词 | 缺邮箱则进入资料补全；市场不符或冲突则系统排除 |
| 搜索发现源 | IP、平台、品类、功能、用户场景、内容形式、本地化 | 优先搜索内容/帖子并回溯作者，再补主页和邮箱；写主表前先做国家/语言与明显语义预检 | 按来源统计合格可触达产出；连续低产自动冷却换源 |

这一区分符合第一性原理：目标是获得合适且可触达的KOL，不是把所有信息都加工成搜索词。
