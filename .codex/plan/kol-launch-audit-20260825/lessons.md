# 本次审计经验

- n8n `success` 只代表启动请求被受理，必须继续回读后台 job 和业务产物。
- 品牌邮箱 24 小时用量包含其他任务，不能代替活动级开发信统计；活动口径要从参与记录关联草稿计算。
- 外部任务汇总里的“有效邮箱数”不是可逐人使用的候选；必须有活动ID、任务ID、词源、发现词四项来源标记，才能安全进入活动漏斗。
- `lark-cli` 当前生产机入口为 `C:/Users/Administrator/bin/lark-cli.exe`，v1.0.64 的 Base 读命令为 `base +record-list/+record-get`，不是旧版嵌套命令；调用前应先读 `--help`。
- 生产只读检查脚本不能假设存在 `load-env.ps1`，应从 Process/User 环境读取并且只输出变量存在性或脱敏结果；PowerShell 的 `foreach` 结果要先赋给变量，再传给 `ConvertTo-Json`，避免空管道解析错误。
- n8n MCP 认证失败时，不应尝试更改认证或工作流；可回退到已验证的 n8n REST 只读接口，并严格隐藏 API key 和工作流 Authorization 值。
- 飞书任务的长执行日志可能被字段上限从左侧截断；看到残缺 Traceback 时不能猜最终异常，必须按 task record_id 和时间回查部署终端原始 `daemon.log`，拿到最后一行异常后再决定是否修代理、HTTP 处理或外部源适配。
- `/jobs/latest` 在当前进程命中内存任务时，内存字典必须显式带 `job_id`；否则响应虽然状态正确，却会把路由参数 `latest` 当 job_id，削弱单任务审计。持久状态测试不能替代当前进程响应测试。
- `C:/tmp/py311-embed/python.exe` 的固定搜索路径可能优先导入其他临时仓库里的同名 `app`。在多个 Python 项目之间跑测试时，必须显式把当前仓库绝对路径插入 `sys.path[0]`，并在首轮核对模块 `__file__`；不要靠当前工作目录猜导入来源。
- 活动草稿如果被多个活动参与记录同时关联，所有新增漏斗阶段都必须复用同一排除集合；只在最终发送统计中排除会造成回复/寄样数字虚高。
