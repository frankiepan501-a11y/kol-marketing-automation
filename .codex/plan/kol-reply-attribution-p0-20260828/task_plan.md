# KOL 回复活动归属 P0（2026-08-28）

## 目标

未能自动匹配原邮件或集中宣发活动的 KOL 回复，不再被日报静默排除；系统把仍有业务价值的回复发成运营归属卡，由运营在当前活动中选择归属后继续原回复流程。回绝、合作结束后的纯道谢等终态/无关消息直接收口，不制造无意义卡片。

## 验收标准

- 未知原邮件 ID、缺少唯一活动归属、跨活动冲突，都会进入“待确认活动归属”队列，而不是只有数据异常文字。
- 卡片展示：KOL、产品、回复摘要/意图、候选活动、任务性质、目标上稿数、窗口结束/承诺或规定上稿时间、运营下一步。
- 卡片只允许一个表单提交按钮；`value.action` 稳定，回调可幂等，处理后 PATCH 原卡。
- 运营选择活动后，归属持久化，并继续既有 reply 审核/回复路径；回绝或无关信息进入终态。
- 食人花全部未归属回复完成只读盘点；真实运营批量卡只在 Frankie-only 样卡验证后发送。
