# 客服邮件误派 KOL 修复计划

## 最初目标

修复平台代发的红人/创作者/联盟合作邮件被客服助手当成独立站客诉的问题，并纠正已确认的 3 条生产工单。

## 当前已授权范围

- 修改 `kol-automation` 中客服收件与分流代码。
- 新增确定性的 KOL 合作意图硬闸，避免模型误判后继续派给独立站运营。
- 通过 ACTIVE 的 KOL媒体助手发送无客户外发副作用的内部待审核卡。
- 纠正已确认的 3 条客服工单；更新/撤销其旧客服卡，并给当前临时 KOL 负责人发送审核卡。
- 部署到生产并做单条回读验证。

## 明确不做

- 不自动回复红人，不生成或发送合作邮件。
- 不自动承诺费用、寄样、广告使用权或内容二次使用权。
- 不扩大飞书 App 权限、人员范围、群路由或回调。
- 不把所有 B2B/供应商合作都改成 KOL。
- 不批量修改未确认的模糊记录。

## 完成条件

1. 回归测试证明 3 类明确合作语义不会再进入独立站客服队列，普通客诉不被误拦。
2. 平台代发邮件能使用正文内真实联系人匹配既有 KOL；新创作者明确标为未入库待审核。
3. 生产部署版本可核验，健康检查通过。
4. 3 条工单状态改为非客服/KOL转交，旧客服卡不再可处理。
5. KOL媒体助手的 3 张内部审核卡发送成功且消息可回读。
6. 无客户邮件发送，无新增 KOL 主表记录，无重复卡。

- [completed] 2. 最小代码修复与定向测试

- [completed] 6. 修复记录与收尾
