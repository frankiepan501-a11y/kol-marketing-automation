# 集中宣发待审旁路与体量优先修复

## 目标

让 Dave 与食人花活动在存在待审核候选时，仍持续扩展候选来源、补入系统明确合格者、生成合格草稿并由唯一发送中心按邮箱额度发送；人工审核只处理边界项，不再成为开发和发信的前置阻塞。

## 范围

- 修改活动候选自动补入与自治补池控制逻辑。
- 修改活动关键词供给的低产处理：额度和可发库存仍有缺口时继续有限扩展，不降低硬筛选。
- 保留未审核对象不得生成草稿、不得发送的安全线。
- 本阶段只完成本地代码、测试、审查和提交；不部署、不手动触发生产任务、不改 n8n 开关。

## 执行假设

- 用户所说“不能因为没审核而停止开发信”解释为：继续寻找并发送其他系统明确合格对象；不是把不确定对象未经审核直接发出去。
- 每日数量是控制目标，系统应持续尝试补足；若公开渠道没有足够合格对象，必须明确显示供给缺口，不能伪造“已满足”。

## 验收标准

1. 任何活动自动补入入口都不会因为已有待审核记录返回阻塞。
2. 待审核记录不进入草稿与发送队列，系统明确合格者可并行进入。
3. 当邮箱额度仍有余量且可发送库存不足时，低产冷却不得让整轮发现任务为 0；创建数量仍受原有 3～9 个任务上限和在途任务去重控制。
4. 国家、语言、内容、活跃度、邮箱、历史关系和重复触达规则不降低。
5. 聚焦测试与全仓测试通过，双轴代码审查无 P0/P1 问题。
